Scope of this data

What this is, and what it isn't. This comes from Jira's /project/CDLC/statuses endpoint, which any user with Browse Projects permission can read. It returns, for every work type, the full set of statuses in that work type's workflow.

Usage is measured, not assumed. Each row carries how many tickets that work type has ever had and how many in the last twelve months. Anything with no ticket in a year reads Dormant; one type has never been used at all. Counts were taken against all 7,951 CDLC issues on 27 August 2026 and are a snapshot, not a live feed.

It does not return transitions or order. The arrows Jira draws in the issue-view workflow diagram come from workflow configuration, which only a Jira administrator can export. So the chips below are the complete status set for each work type, but the sequence they appear in is not meaningful.

Where this comes from

Jira does not keep a readable history of workflow configuration. There is no changelog for "this status was added on this date". What exists is the trail of tickets that asked for each change, and almost all of them live under one epic: SGP-9551 "CDLC Changes", opened 13 April 2026 and described as "Changes for existing CDLC workflows, automations, fields, etc." Its tree holds 83 tickets. Seven more sit outside it.

So this is a log of intent, verified against current state where possible. Shipped means the ticket was closed, and where the live status data confirms the change landed, the before and after are shown. Anything before November 2025 was not recorded in a way that survives.

Where this comes from

This half is not from Jira. It comes from the CDLC Process Documentation, the Content Team's SOP — version 1.0, effective 30 May 2026, owned by the QA Specialist. Jira holds the statuses; the SOP holds the sequence, the ownership and the automation chain, which is why the two are shown side by side.

Six names in the SOP do not match Jira, and they are marked on the stages below. The SOP's own workflow diagrams did not survive its export to Markdown — all 34 came through as empty images — so the transitions still have to come from Jira admin access.
